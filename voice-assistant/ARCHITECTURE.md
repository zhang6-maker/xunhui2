# 语音助手骨架项目 - 架构定义

---

## 🏛️ 架构概览

基于 Electron + Vosk + TTS + WebSocket 的语音助手完整骨架。

## 📦 模块定义与边界规则

### 模块：preload 桥接层

**职责**：主进程与渲染进程之间的安全通道

**边界规则**：
- 只暴露方法，不暴露对象。渲染进程不能拿到主进程的任何对象引用。
- 每个暴露的方法必须做参数校验，非法参数直接拒绝，不能传到主进程。
- 渲染进程不能通过 preload 访问文件系统、不能直接调 Vosk、不能直接调 WebSocket。
- 所有 API 调用必须记录日志，便于追踪和审计。
- 禁止暴露 Electron 的原生模块（如 `fs`、`path`、`shell`）给渲染进程。

**暴露的 API 列表**：
| API 方法 | 功能 | 参数校验要求 |
|----------|------|--------------|
| `startListening()` | 启动语音识别 | 无参数，直接调用 |
| `stopListening()` | 停止语音识别 | 无参数，直接调用 |
| `speak(text)` | 执行语音合成 | 校验 text 必须是非空字符串 |
| `sendMessage(type, data)` | 发送 WebSocket 消息 | 校验 type 必须是预定义类型 |
| `getStatus()` | 获取当前状态 | 无参数，直接调用 |

---

### 模块：主进程协调器

**职责**：唯一的跨模块调度者，负责编排所有流程

**边界规则**：
- 这是唯一有权调度 Vosk、TTS、WebSocket 的模块。
- Vosk 不知道 TTS 的存在。TTS 不知道 WebSocket 的存在。
- 所有跨模块的流程（识别→发消息→收回复→播报）必须写在协调器里。
- 协调器不直接处理业务逻辑，只负责流程编排。
- 所有外部事件（IPC、WebSocket）必须经过协调器转发。

**核心流程编排**：
```
语音识别流程：
  Renderer → IPC → Coordinator → Vosk → Coordinator → IPC → Renderer

语音合成流程：
  Renderer → IPC → Coordinator → TTS → Coordinator → IPC → Renderer

WebSocket消息流程：
  Client → WebSocket → Coordinator → (Vosk/TTS/Renderer) → Coordinator → WebSocket → Client
```

---

### 模块：Vosk 语音识别

**职责**：收音频数据，返回识别文本

**边界规则**：
- 只做一件事：处理音频流，输出识别结果。
- 不知道有 TTS，不知道有 WebSocket，不知道有渲染进程。
- 识别失败返回错误，不负责重试，不负责通知 UI。
- 不维护任何状态，每次识别都是独立的。
- 只接受协调器的指令，不直接响应其他模块的调用。

**输入输出规范**：
- **输入**：音频数据流（PCM，16kHz，单声道）
- **输出**：识别文本字符串，或错误对象

---

### 模块：TTS 语音合成

**职责**：接收文本，输出语音

**边界规则**：
- 只做一件事：接收文本，生成并播放语音。
- 不知道有 Vosk，不知道有 WebSocket，不知道有渲染进程。
- 播放失败返回错误，不负责重试，不负责通知 UI。
- 不维护播放队列，同一时间只能处理一个请求。
- 只接受协调器的指令，不直接响应其他模块的调用。

**输入输出规范**：
- **输入**：文本字符串
- **输出**：无返回值（异步播放），或错误对象

---

### 模块：WebSocket 服务器

**职责**：管理客户端连接，处理消息收发

**边界规则**：
- 只做一件事：维护 WebSocket 连接，转发消息。
- 不知道有 Vosk，不知道有 TTS，不知道业务逻辑。
- 不处理消息内容，只负责消息的路由和转发。
- 连接管理（建立/断开/心跳）由服务器独立完成。
- 只接受协调器的指令，不直接响应其他模块的调用。

**消息协议规范**：
- **客户端 → 服务器**：`{ type: string, data: any }`
- **服务器 → 客户端**：`{ type: string, data: any, timestamp: number }`

---

### 模块：渲染进程状态机

**职责**：管理应用状态转换和通知

**边界规则**：
- 只管理状态转换和通知。
- 不能直接操作 DOM。DOM 操作是视图层的活。
- 不能直接调 IPC。调 IPC 是专门的通信模块的活。
- 状态机只发内部事件，通信模块监听这些事件去调 IPC。
- 状态转换必须有明确的触发条件和前置状态检查。

**状态定义**：
| 状态 | 说明 | 允许的转换 |
|------|------|------------|
| `idle` | 空闲状态 | → listening |
| `listening` | 正在识别 | → idle, speaking |
| `speaking` | 正在播报 | → idle |
| `error` | 错误状态 | → idle |

---

### 模块：视图层

**职责**：展示 UI、处理用户交互

**边界规则**：
- 只做两件事：渲染界面、监听用户操作。
- 不包含业务逻辑，所有决策都交给状态机。
- 不直接调 IPC，通过事件总线触发状态机。
- 状态变更只能通过订阅状态机的事件来感知。
- 纯展示组件，不持有任何业务数据。

## 🔒 架构宪法

### 第一条：单向数据流

所有数据流向必须遵循以下路径：
```
用户操作 → 视图层 → 状态机 → 通信模块 → preload → 协调器 → 业务模块
业务模块 → 协调器 → preload → 通信模块 → 状态机 → 视图层 → 用户
```

### 第二条：禁止跨层调用

- 渲染进程不能直接调用主进程的模块
- 业务模块之间不能互相调用
- 视图层不能直接操作业务数据

### 第三条：单一职责

每个模块只负责一件事：
- Vosk：只做识别
- TTS：只做合成
- WebSocket：只做通信
- 协调器：只做编排
- 状态机：只做状态管理
- 视图层：只做展示

### 第四条：参数校验

所有跨模块调用必须进行参数校验：
- preload 层必须校验所有来自渲染进程的参数
- 协调器必须校验所有发往业务模块的参数
- 非法参数必须在入口处拒绝，不得传入内部

### 第五条：错误隔离

错误必须在产生的模块内处理或向上抛出：
- Vosk 识别失败 → 返回错误 → 协调器处理 → 通知状态机 → 更新 UI
- 禁止在业务模块中直接通知 UI
- 禁止在 UI 层中直接处理业务错误

## 📊 模块间通信协议

### IPC 通信（渲染进程 ↔ 主进程）

**渲染进程 → 主进程**：
| 通道名 | 数据结构 | 用途 |
|--------|----------|------|
| `start-listening` | `{}` | 启动语音识别 |
| `stop-listening` | `{}` | 停止语音识别 |
| `speak` | `{ text: string }` | 执行语音合成 |
| `send-message` | `{ type: string, data: any }` | 发送 WebSocket 消息 |

**主进程 → 渲染进程**：
| 通道名 | 数据结构 | 用途 |
|--------|----------|------|
| `voice-result` | `{ text: string }` | 语音识别结果 |
| `status-change` | `{ status: string }` | 状态变更通知 |
| `error` | `{ message: string }` | 错误通知 |

### WebSocket 消息协议

**客户端 → 服务器**：
```javascript
// 语音识别结果
{ "type": "voice", "text": "识别到的文本" }

// TTS播放请求
{ "type": "tts", "text": "要播放的文本" }

// 命令
{ "type": "command", "command": "start_listening" | "stop_listening" }
```

**服务器 → 客户端**：
```javascript
// 语音识别结果广播
{ "type": "voice_result", "text": "识别到的文本", "timestamp": 1234567890 }

// TTS播放完成
{ "type": "tts_finished", "timestamp": 1234567890 }

// 状态更新
{ "type": "status", "status": "idle" | "listening" | "speaking" }
```

## 🛡️ 安全规则

### 渲染进程安全
- 禁止 eval() 和 new Function()
- 禁止内联脚本执行
- 所有外部数据必须经过 sanitize 处理

### preload 安全
- 禁止暴露 Node.js 原生模块
- 禁止暴露 Electron API
- 所有参数必须进行类型和范围校验

### 主进程安全
- WebSocket 连接必须验证来源
- 消息内容必须进行格式校验
- 禁止执行用户输入的代码
