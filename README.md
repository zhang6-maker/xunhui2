## 各模块说明

### main.js — Electron 主进程

负责创建窗口、启动后台服务、处理 IPC 通信。

主要功能：
- 创建透明无边框主窗口（400×500，右下角）
- 启动 Edge-TTS Python 服务（端口 8001）
- 启动网易云音乐 API 服务（端口 3000）
- 创建 HTTP 服务（端口 8080，手机遥控页面）
- 创建 WebSocket 服务（端口 8083，手机通信）
- 处理 PPT 模板保存/填充、语音识别、文件对话框等 IPC 请求

与原版的区别：路径全部改为相对于 `v2/` 目录，完全独立运行。

---

### preload.js — 安全预加载脚本【第一阶段重构】

原版直接暴露了完整的 `require`，任何渲染进程代码都能访问系统文件。重构后改为白名单机制。

改动内容：
- 通过 `contextBridge` 暴露 `window.electronAPI`，只包含明确允许的方法
- IPC 通道白名单：`invoke` 和 `send` 各有独立的允许列表，未授权通道直接拒绝
- 文件读写路径校验：`isPathAllowed()` 函数确保只能读写 `homedir` 和 `tmpdir` 下的文件，禁止访问系统敏感路径（如 `C:\Windows\System32`）

---

### timerManager.js — 全局定时器管理【新增，第一阶段】

原版中 `setTimeout`/`setInterval` 散落在各模块，组件销毁时无法统一清理，导致内存泄漏和残留定时器引发的重复动作。

功能：
- `TimerManager.setTimeout(group, fn, delay)` — 注册定时器，归属某个分组
- `TimerManager.setInterval(group, fn, interval)` — 注册循环定时器
- `TimerManager.clearGroup(group)` — 清除某分组下所有定时器
- `TimerManager.clearAll()` — 清除全部定时器（应用退出时调用）
- `TimerManager.debug()` — 打印当前活跃定时器数量（调试用）

已接入 TimerManager 的模块：`drag.js`（饥饿定时器）、`reminders.js`（提醒检查）、`index.js`（启动定时器）。

---

### state.js — 状态机【第二阶段重构】

原版用 30 行 if-else 豁免条件判断状态切换，逻辑分散，容易出现未定义行为。

重构内容：

**冷却锁保留**：`minDuration`（默认 10 分钟）防止状态频繁切换，短暂状态（eating/working/playing/walking/stretching/dancing）有豁免列表，与原版完全一致。

**自动结束定时器集中管理**：进入某些状态时自动注册结束定时器，用 `_stateAutoEndTimer` 统一管理，切换状态时先清除旧定时器再注册新的，彻底解决重复动作问题：
- `waking` → 2.5 秒后自动切到 `stretching`
- `stretching` → 2 秒后自动切到 `idle`
- `dancing` → 4 秒后自动切到 `idle`

**GIF 强制重播**：对 `waking/stretching/playing/dancing/eating/working` 这些需要从第一帧播放的状态，先清空 `src` 再赋值，解决浏览器复用缓存帧导致动画不播放的问题。

**startRandomPlay 修复**：只在 `idle` 状态下才注册下一轮随机玩耍定时器，非 idle 时停止递归，解决重复动作 bug。

状态流转图：
```
idle ←→ walking → working → stretching → idle
idle ←→ walking → sleeping ←→ waking → stretching → idle
idle → playing → idle
idle → eating → idle
idle → dancing → idle
```

---

### actions.js — 动作模块【第三阶段重构】

原版有两套并存的 PPT 生成方案（从零生成 + 模板生成），维护两份代码。

改动内容：
- **PPT 生成统一**：合并为单一入口 `generatePPT(topic)`，优先使用模板，无模板时自动降级到 pptxgenjs 从零生成，删除重复代码
- **feed() 双重触发修复**：用本地 `finished` flag 防止安全定时器和 `onEnd` 回调同时触发 `eating→idle`
- **dance() 修复**：不再依赖 dispatch，直接调用 `setState('dancing')`，结束定时器由 state.js 统一管理
- **handleUserInput 唤醒修复**：睡眠时调用 `setState('waking')` 而非 `dispatch('wake')`，确保自动推进链生效

---

### chat.js — 对话模块【第三阶段重构】

原版 `talkToOllama` 函数超过 200 行，所有逻辑混在一起。

拆分为 6 个职责单一的函数：
1. `_interceptBuiltinCommands` — 内置指令拦截（提醒/音乐/搜索/报时/日期）
2. `_matchCannedReply` — 预设回复匹配（学习型对话）
3. `_buildSystemPrompt` — 构建系统提示词（好感度/性别/人格）
4. `_streamOllamaResponse` — 调用 Ollama API 并处理流式响应
5. `_handlePostReply` — 回复后处理（嫌弃表情/内心戏/日记/动作触发）
6. `talkToOllama` — 主入口，串联以上步骤

**时间解析修复**：`parseRemindTime` 补全了所有时间段处理（凌晨/早上/上午/中午/下午/傍晚/晚上），新增自动顺延逻辑——如果解析出的时间已经过了，自动顺延到明天同一时间。

---

### reminders.js — 提醒模块【重构】

原版触发提醒时只显示一行气泡 + 朗读内容，体验很弱。

改动内容：
- **AI 生成提醒话语**：触发时调用 `talkToOllama` 生成有感情的提醒，prompt 要求必须把提醒内容完整说出来，并结合好感度调整语气
- **立即显示气泡**：不等 AI 响应，先立刻显示 `⏰ 提醒：xxx` 气泡，确保用户第一时间看到
- **重复提醒**：30 秒后如果未确认，再提醒一次；再过 60 秒最后提醒一次，之后停止
- **睡眠唤醒**：如果精灵在睡觉，先触发 `setState('waking')` 唤醒动画，再延迟 3 秒显示提醒

---

### index.js — 入口初始化【重构】

改动内容：
- **TTS 检测修复**：原版用合成请求检测服务是否就绪，合成本身耗时超过 2 秒超时导致误判。改为 GET 请求访问 FastAPI 的 `/docs` 端点，响应极快，只要服务进程在跑就能立刻返回
- **TTS 失败不阻断**：即使 TTS 检测超时，也继续显示启动语，TTS 模块内部有浏览器语音降级，不会完全无声
- **点击唤醒流程**：`setState('waking')` 后由 state.js 自动推进 waking→stretching→idle，不再手动注册多个 setTimeout

---

### deps.js — 依赖注入

将所有系统能力（文件系统、路径、IPC、shell）封装为 `window.DEPENDENCIES` 对象，渲染进程模块通过此对象访问，不直接使用 `require`。

与原版相同，无功能改动。

## 运行效果

启动后：
1. 精灵出现在屏幕右下角，播放待机动画
2. 等待 TTS 服务就绪（检测 `/docs` 端点），就绪后 AI 生成傲娇开场白并朗读
3. 每 30 秒随机切换待机动画，10% 概率触发"自言自语"内心戏

交互：
- 点击精灵 → 弹出输入框，可以打字或点麦克风说话
- 说"去工作" → 精灵走到工作位，播放工作动画，3 秒后伸懒腰，回到待机
- 说"睡觉" → 精灵走到床位，播放睡觉动画，响起呼噜声
- 点击睡觉中的精灵 → 播放睁眼动画（wake.gif），伸懒腰，恢复待机，触发起床气 AI 对话
- 说"提醒我下午3点开会" → 到点后 AI 生成提醒话语朗读，30 秒后未确认会再次提醒
- 拖拽食物图标到精灵身上 → 触发喂食，AI 生成被投喂的傲娇反应
- 右下角眼睛按钮 → 隐藏/显示精灵，拖动按钮可移动整个窗口
- 按 Ctrl+Shift+H → 强制显示精灵（隐藏后找不到时用）

## V2 深度重构与性能优化记录

### 1. 独立运行能力重构 (Standalone Reconstruction)
为了实现 `v2` 文件夹的完全解耦和独立运行，进行了以下迁移：
- **依赖内置**：将 `python_portable` (Python 环境)、`bin/vosk-model-cn-0.22` (语音识别模型) 和 `NeteaseCloudMusicApi` 全部迁移至 `v2` 目录下。
- **路径解耦**：修复了 `main.js` 和所有渲染进程脚本，将所有绝对或父级路径（`../`）替换为基于 `v2` 的相对路径。
- **配置补全**：完善了 `v2/package.json` 中的依赖项列表，支持在 `v2` 内部直接执行 `npm install`。

### 2. TTS 稳定性与“假死”修复 (TTS Stability & Fallback)
针对日志中出现的 Edge-TTS 500/504 错误及网络波动：
- **服务端超时控制**：在 `edge_tts_service.py` 中引入了 20 秒强制超时限制，防止因微软服务器无响应导致的 Python 进程挂起。
- **智能错误识别**：`tts.js` 现在能识别 `getaddrinfo failed` (DNS 错误) 或连接超时。
- **快速降级机制**：一旦检测到严重网络错误，系统将立即停止重试并秒切“浏览器语音”降级方案，用户等待时间从 60s+ 缩短至约 20s。

### 3. 文本处理与语音修正 (Text & Speech Correction)
修复了寻慧在说话时“吞字”或“不读数字”的问题：
- **Emoji 正则修正**：将 `\p{Emoji}` 替换为 `\p{Extended_Pictographic}`。修复了原正则误将数字 `0-9` 识别为表情组件并删除的 Bug。
- **精细化括号清理**：修改正则逻辑，仅移除 5 字符以上的长括号内容（系统提示），保留短括号内的数字或短语。
- **智能数字转中文**：为浏览器语音增加了“数字翻译器”，支持将多位数（如 `87`）转译为中文音节（`八十七`），确保 100% 朗读成功。

### 4. 图片加载稳定性修复 (Image Loading Stability)
解决了精灵偶尔显示空白或切换动作闪烁的问题：
- **时间戳重载机制**：废弃了不稳定的 `src = ''` 重置方案，改用 URL 时间戳（`?t=timestamp`）强制浏览器刷新 GIF 帧，实现了动画的无缝重启动。
- **逻辑去冗余**：将 `playing` 等动作的图片随机选取逻辑从 `actions.js` 统一收拢到 `state.js` 的状态机中，避免了多处脚本争夺图片控制权导致的冲突。

### 5. PPT 生成能力深度增强 (Advanced PPT Generation)
针对原版 PPT 内容单薄、页数过少的问题：
- **AI 自动内容策划**：接入 Ollama 大模型，根据用户主题自动构思 **5-8 页** 的详细内容（含封面、目录、核心观点、总结）。
- **多页模板智能填充**：重构了 `fill_ppt.py`，支持循环遍历 PPT 模板页并智能匹配标题/正文框进行填充，若模板页数不足则按风格自动追加。
- **视觉排版优化**：在“从零生成”模式下，新增了背景色、标题装饰线、列表自动识别以及每一页右下角的“寻慧”动态水印图标。
- **数据结构鲁棒性修复**：针对 AI 偶尔返回对象（如 `{"slides": [...]}`）而非纯数组的问题，在 `main.js` 和 `actions.js` 中增加了自动纠错逻辑，确保 `forEach` 循环不会因数据类型不匹配而崩溃。
- **PPT 专家级视觉与内容升级**：
    - **深度内容构思**：AI 现在会为每页生成主副标题、不少于 200 字的深度正文以及核心要点数组，确保内容不再“浅尝辄止”。
    - **专业排版布局**：支持封面、目录、双栏内容、总结等多种幻灯片布局，并自动添加装饰色块和侧边栏。
    - **视觉助理嵌入**：将寻慧的动态表情包（如工作、思考、跳舞）智能嵌入到幻灯片中，解决了无配图导致的单调感。
- **智能意图识别与主题定制 (V4 升级)**：
    - **AI 辅助主题提取**：不再生硬地截断用户输入，而是先让 AI 理解消息意图，精准提取核心主题。
    - **主题驱动型内容生成**：AI 会根据主题特性（科技/商务/人文）自动规划逻辑架构，确保每一页内容都具备极高的知识含金量和专业洞察力。
    - **视觉主题自适应**：AI 会根据内容建议主色调，排版引擎动态调整幻灯片配色、侧边装饰条和组件样式，使 PPT 整体风格与主题高度统一。
- **全场景布局与情绪交互 (V5 升级)**：
    - **全布局支持**：实现了封面、深度解析、并列要点（卡片式）、总结陈词等全套专业幻灯片布局。
    - **智能模板适配**：重构了 `fill_ppt.py`，采用基于“空间位置”和“形状特征”的启发式算法，能更精准地识别各类第三方 PPT 模板中的占位符。
    - **情绪同步表情包**：AI 会分析每页幻灯片的情感基调（如思考、警告、喜悦），并自动在 PPT 中嵌入寻慧对应的动态表情包，实现内容与视觉的深度共鸣。
- **高可用鲁棒性引擎 (V6 终极增强)**：
    - **Ollama 模型自适应**：系统现在会自动探测本地可用的模型（优先匹配 Qwen 系列），彻底解决了因模型名称不一致（如 `qwen:7b` vs `qwen2:7b`）导致的生成失败。
    - **深度保底逻辑**：即便 AI 生成彻底失败（如断网或模型崩溃），系统也能自动触发一份包含 **5 页完整架构**（封面、原理、战略、风险、行动）的深度研究报告模板，确保功能永不失效。
    - **智能 JSON 修复**：增加了正则表达式预处理，能自动剥离 AI 返回内容中的 Markdown 代码块标签（```json），极大提升了数据解析的成功率。
- **分布式深度撰写引擎 (V7 终极进化)**：
        - **多轮交互逻辑**：彻底重构了生成算法，由“一次性产出”改为“先规划大纲、再逐页深度撰写”的分布式模式。
        - **文稿质量质变**：通过强制性的专家级指令，每一页 PPT 的正文长度提升至 400-600 字，包含深入的行业见解、数据模拟和逻辑推导。
        - **自适应排版引擎**：排版引擎现在能根据文字密度动态调整字号（11-14pt）和行间距，确保高密度的专业信息能完美呈现而不溢出。
        - **全过程进度反馈**：在生成长达 10 页深度内容的过程中，寻慧会分阶段向用户报告进度（构思大纲、深度撰写、校对文稿等），解决了长时间等待的焦虑。
    - **行业研报级“干货”引擎 (V8 终极版)**：
        - **批处理深度生成**：改为“2页一组”批处理模式，既保持了内容的连贯性，又通过并行处理大幅缩短了等待时间。
        - **“去套路化”指令集**：引入了严格的“反废话”提示词，禁止使用 AI 常见的空洞词汇（如“总之”、“核心组件”），强制要求输出具体的行业术语、逻辑链条和实操方案。
        - **多维保底系统**：重构了最后的保底文稿，即便在断网或模型彻底失效的情况下，也能生成包含 6 页、每页字数不少于 300 字的“行业研报级”硬核内容，杜绝了之前的空洞模板。
        - **超时与重连机制**：在主进程中引入了带超时的 fetch 逻辑，有效防止了 Ollama 因负载过高导致的界面死锁。

### 6. 安全架构与沙箱优化 (Security & Sandbox)
- **IPC 通道白名单**：在 `preload.js` 中建立严格的白名单机制，补全了 `generate-ppt-content`、`select-ppt-template` 等新增功能的通信授权，确保在提升功能的同时不破坏系统的安全沙箱。

### 7. UI/UX 体验细节
- **内心戏延长**：将“心里说话”气泡的显示时间从 3s 延长至 **4-5s**，确保你有足够的时间阅读寻慧那些傲娇的小心思。
- **语音数字保护**：通过正则负向先行断言（Negative Lookahead），彻底解决了语音清洗过程中误删数字（如时间、页码）的问题。
